BCIJelly 首页移动端响应式改造设计

目标​

在不改变桌面版视觉效果和交互行为的前提下，使 BCIJelly 首页及相关文档正文能够在宽度不超过 996px 的平板和手机上正常显示。改造必须消除横向溢出，保证中英文内容可读，并保留现有五个首页区块、导航、链接和翻译逻辑。

成功标准​

  • 视口宽度大于 996px 时，Hero、About、Features、Team 和 Footer 与改造前保持相同位置、尺寸和视觉层级。
  • 360px、390px、768px 和 996px 宽度下，中文和英文首页均无页面级横向滚动。
  • 移动端导航、功能标签切换、教程链接、语言切换和首页下滑锚点均可使用。
  • 文档页桌面正文仍保持当前 max-width: 85%，移动端正文恢复为 100%。
  • Docusaurus production build 成功完成。

已确认的视觉选择​

  1. Hero：采用移动端重新组合方案。保留现有大脑主体图，用渐变遮住原图内会被裁断的烘焙文字，并用可换行、可翻译的 HTML 文本重新呈现标题和机构名称。
  2. About：采用“图片在上、正文在下”的移动端结构。
  3. Features：采用横向滑动标签；功能内容改为“配图、标题与描述、教程按钮”的单列顺序。
  4. Team：手机采用两列网格，第七位成员居中；平板根据宽度使用三至四列。
  5. Footer：Logo 使用 2×2 网格，链接和版权信息使用单列，联系方式逐行显示。

实现策略​

采用“语义化 class + CSS 媒体查询”方案。首页中的布局型内联样式迁入 src/css/custom.css，桌面基础规则复制当前有效值，移动端规则仅写在最大宽度媒体查询中。

不采用以下方案：

  • 不使用大量 !important 覆盖现有内联样式，因为其优先级关系脆弱，后续难以维护。
  • 不创建一套独立的移动端首页组件，因为这会复制五个区块的结构、翻译和链接逻辑。
  • 不使用 JavaScript 读取视口宽度，避免 Docusaurus SSR 水合差异。

文件与职责​

src/pages/index.js​

  • 在首页主节点增加 .home-page，并根据语言增加 .home-page--en 或 .home-page--zh。
  • 为 Hero、About、Features、Team 和 Footer 中的布局容器增加语义化 class。
  • 将 height、display、flex、gap、margin-left、宽度、字号和区块间距等布局型内联样式迁入 CSS。
  • 保留翻译调用、功能数据、activeTab 状态、图片引用和链接行为。
  • 将 Footer 联系信息拆为独立 <span>，桌面横排、移动端逐行。
  • 不修改站点导航项目和文档数据。

src/css/custom.css​

  • 所有首页新规则限定在 .home-page 下，避免影响文档主题。
  • 桌面基础样式使用当前页面实际生效的数值，不重新设计桌面端。
  • 使用以下响应式层级：
    • @media (max-width: 996px)：Docusaurus 导航折叠临界点和平板布局。
    • @media (max-width: 768px)：手机主体布局。
    • @media (max-width: 480px)：小屏字号、间距和成员卡片微调。
  • 添加 prefers-reduced-motion 规则，减少 Features 图片切换位移动画。
  • 文档正文的 85% 宽度只在移动端覆盖为 100%。

i18n/en/code.json 与 i18n/zh/code.json​

  • 新增移动端 Hero 标题和机构名称翻译键。
  • 不覆盖或重写现有翻译。
  • 实施时必须保留当前工作区中 i18n/en/code.json 的未提交改动，包括团队职称文本。

docusaurus.config.js​

本次不修改。Docusaurus 的默认移动端导航折叠行为继续在 996px 生效。

src/pages/index.module.css​

该文件未被 index.js 引用。实施时删除，避免残留无效媒体查询造成维护误解；删除不会改变现有页面输出。

区块详细设计​

Hero​

桌面端继续使用当前 100vh 横向图片、底部 SVG 圆弧和下滑链接。

移动端：

  • 高度改用稳定的 svh 计算，并设置合理最小高度，避免移动浏览器地址栏引发跳动。
  • 原图使用 object-fit: cover 聚焦大脑主体，但在下半部分叠加由透明到浅蓝背景的渐变，完全遮住被裁切的原图文字。
  • 渐变区域上渲染新的中英文 HTML 标题和机构名称。
  • 保留底部圆弧与下滑链接，并缩小其高度和字号以适应窄屏。
  • 图片加载失败时保留浅蓝背景和可访问的 alt 文本。

About​

桌面端继续保持背景大脑位于左侧、正文位于右侧。

移动端：

  • 取消 margin-left: 40rem、固定大宽度和 min-height: 900px。
  • 背景图在区块顶部显示为独立视觉区域，聚焦脑图主体。
  • 正文位于其下方的深色区域，宽度为容器宽度，左右安全间距约 20px。
  • 标题、段落和粗体颜色沿用当前设计，并允许中英文自然换行。

Features​

桌面端继续保持标签横排、左文右图。

移动端：

  • 标签容器启用原生横向滚动、单行显示和滚动吸附，并隐藏视觉滚动条。
  • 标签与操作按钮的触控高度不低于 44px。
  • 内容容器切为单列，图片通过 CSS order 放在正文之前。
  • 图片宽度限制为容器的 100%，取消桌面的 120% 放大和 40px 横移。
  • 标题、描述和按钮不使用固定高度；长英文允许自然换行。
  • activeTab 状态和淡入动画逻辑保持不变。

Team​

桌面端继续显示上排三人居中、下排四人。

移动端：

  • 在不复制成员数据的前提下，将两个成员行作为一个视觉网格处理。
  • 手机显示两列，第七张卡片跨两列区域并以半宽居中。
  • 平板根据可用宽度显示三至四列。
  • 卡片保持当前图片比例、圆角和文字覆盖层。
  • 姓名与职称字号使用受限的响应式值，避免英文覆盖或溢出。
  • 触屏设备不依赖 hover 才能看到成员信息。

Footer​

桌面端继续保持四个 Logo 横排、两列文字和单行联系方式。

移动端：

  • Logo 容器切为两列网格，共两行。
  • 超级链接和版权说明依次单列排列，并取消语言相关的固定左偏移和固定 flex 宽度。
  • 联系方式的独立 <span> 逐行显示，不再依赖多个不换行空格分隔。
  • 蓝色联系条与默认版权条均限制文本宽度并允许安全换行。

Navbar 与文档页​

  • Navbar 沿用 Docusaurus 默认折叠菜单，只增加防止标题或控件撑宽页面的移动端约束。
  • 不修改导航项目、版本选择、语言选择或 GitHub 链接。
  • 文档页的当前 85% 宽度规则在桌面保持不变；最大宽度 996px 时覆盖为 100%。

状态、错误和可访问性​

  • 页面唯一局部交互状态仍为 Features 的 activeTab，响应式布局不新增状态。
  • 不访问 window 或依赖客户端首次渲染尺寸。
  • 所有可点击标签和按钮保留键盘可操作性与可见焦点。
  • 现有图片 alt 文本保留；新增的装饰性渐变不进入可访问性树。
  • 中英文文本不设固定内容高度，避免翻译长度变化导致裁切。
  • 页面任何宽度均不使用 overflow-x: hidden 掩盖布局错误；横向滚动仅限 Features 标签容器。

验证计划​

自动与构建检查​

  • 运行 Docusaurus production build，确认中英文资源、链接和 CSS 均可编译。
  • 在各目标宽度检查： document.documentElement.scrollWidth === document.documentElement.clientWidth。

视觉检查​

中文和英文分别检查：

  • 360×800
  • 390×844
  • 768×1024
  • 996×适当高度

桌面回归检查：

  • 1024×768
  • 1440×900
  • 1920×1080

实施前后对同尺寸桌面截图进行对比。任何大于 996px 的区块位置、尺寸、间距或图片裁切变化都视为回归并必须修正。

交互检查​

  • Docusaurus 移动端导航展开和关闭。
  • 中文与英文语言切换。
  • Hero 下滑锚点。
  • 四个 Features 标签切换及横向滑动。
  • 教程链接与外部链接。
  • Team 姓名和职称在触屏及桌面上的可读性。
  • 首页 Footer 和 Docusaurus 默认版权区的换行。
  • 至少一个中文和一个英文文档页在手机与桌面宽度下的正文布局。

非目标​

  • 不重新设计桌面首页。
  • 不修改导航信息架构、文档内容、团队数据或功能文案。
  • 不调整站点 baseUrl、部署配置或版本配置。
  • 不引入新的 UI、轮播或响应式工具依赖。
  • 不重构与首页移动端兼容无关的文档样式。

风险控制​

  • 最大风险是迁移内联样式时改变桌面优先级或遗漏语言差异。实施时先复制当前有效值，再增加移动端覆盖，并通过桌面截图对比验收。
  • Hero 原图包含烘焙文字。移动端渐变必须在 360px 和 996px 两端都完全遮住原图文字，避免与 HTML 文案重叠。
  • Team 当前由两行独立 DOM 组成。移动端合并视觉网格时必须确保桌面行结构和成员顺序不变。
  • 工作区已有 i18n/en/code.json 未提交修改。实施和提交必须只包含明确需要的新增翻译，不能丢失或覆盖用户改动。
